# 基于紫光同创 FPGA 的任意角度畸变矫正：初始方案

> 文档状态：赛前初始方案
>
> 目标平台：紫光同创盘古 50K（MES50HP，PGL50H）
>
> 说明：本文将题面中的要求与工程建议分开。题面要求以官方完整赛题、补充说明和现场规则为准；本文中的分辨率、帧率和模块划分是便于落地的初始假设。

> 开发方式：以 VS Code + Codex 为主，PDS 作为紫光 FPGA 的官方综合、布局布线、位流生成和下载后端。不要把 PDS GUI 当作日常代码编辑器，也不要让 Codex 盲目替代 PDS 的器件/IP/时序流程。

## 1. 题目理解

从现有题面截图看，本题的核心不是目标检测或 YOLO，而是一个面向真实相机图像的 FPGA 图像校正系统，至少包含三类工作：

1. 解析或获得相机内参矩阵，包括焦距和主点。
2. 估计畸变参数，例如径向畸变参数 `k1`、`k2`，必要时增加 `k3`、切向畸变参数 `p1`、`p2`。
3. 在 FPGA 上对实时图像执行矫正，并用测试图卡、MTF50/SFR、直线度和边缘质量评价结果。

题目中的“任意角度”需要重点确认其准确含义：可能指相机或测试卡以任意角度放置后的透视/旋转矫正，也可能进一步要求镜头径向畸变矫正。初始架构应同时预留旋转、透视和径向映射的接口，但开发顺序先从可控的旋转和径向畸变开始。

## 1.1 最终目标边界

本文的最终目标不是只完成“固定角度旋转演示”，而是完成一套可以覆盖题目全部任务的系统：

1. 能采集真实摄像头图像，并稳定输出实时视频。
2. 能在 PC 端完成相机标定，得到内参矩阵和畸变参数。
3. 能通过上位机将标定参数、任意角度和矫正模式下发给 FPGA。
4. FPGA 能执行旋转、透视/姿态变化和镜头畸变的组合校正。
5. 支持双线性插值、边界填充和可配置输出窗口。
6. 通过 HDMI 实时显示原图、矫正图和测试叠加结果。
7. 能用测试卡完成矫正前后的直线度、边缘质量、SFR/MTF50 对比。
8. 上位机能保存标定参数、抓取画面、显示指标并生成测试记录。
9. 能给出资源占用、帧率、延迟、误差和不同角度下的稳定性报告。
10. 最终形成可复现的 VS Code 工程、PDS 工程、RTL、模型、上位机、测试数据、视频和设计文档。

因此，本文中的“阶段 1/2/3”只是逐步实现完整系统的顺序，不代表最终方案可以停留在简化模型上。

## 2. 预期系统形态

推荐的首版系统如下：

```text
OV5640 DVP 摄像头
        |
        v
FPGA 图像采集与 RGB565 解码
        |
        v
DDR3 帧缓存 / 行缓存
        |
        v
坐标反向映射：旋转、透视、径向畸变
        |
        v
最近邻或双线性插值
        |
        +--> HDMI 显示器：实时矫正画面
        |
        +--> HDMI 采集卡：电脑上位机显示/录制
        |
        +--> UART：参数配置、状态、MTF/SFR 结果
```

### 2.1 摄像头建议

优先选用 OV5640 单目 DVP 摄像头模块。原因是公开资料中已有盘古 50K 配套使用案例，DVP 并行接口比 USB 或 MIPI 更适合 FPGA 初学阶段，且可以从 VGA/640×480 模式开始。

首版建议配置：

- 分辨率：640×480；
- 数据格式：RGB565；
- 输入接口：DVP，包含 `PCLK`、`VSYNC`、`HREF` 和数据线；
- 控制接口：SCCB/I2C，用于设置分辨率、输出格式和曝光；
- 镜头：固定焦距、可手动对焦优先，避免自动对焦导致标定参数变化。

不建议首版使用 USB 摄像头或 MIPI 摄像头。USB 会引入 USB Host/协议处理，MIPI 会引入差分接收和更复杂的物理层/IP，都会偏离本题的核心算法。

### 2.2 视频输出与电脑连接

FPGA 的实时视频优先走 HDMI：

- 直接接显示器，用于现场演示；
- 接 HDMI USB 采集卡，用于电脑上位机显示、录制和对比。

UART 不承担实时视频传输，只用于下发角度、内参、畸变系数和读取帧率、延迟、MTF/SFR 等结果。若后续确实需要电脑直接接收原始视频，再考虑 UDP/以太网，不作为第一版主线。

## 3. 算法方案

### 3.1 软件黄金模型优先

先使用 Python/OpenCV 建立参考结果，输入一张相机拍摄的棋盘格或 SFR 图，完成：

- 相机内参标定；
- 畸变系数估计；
- 旋转/透视变换；
- 径向和切向畸变矫正；
- 最近邻和双线性插值对比；
- 输出矫正图、边缘图、直线度误差和 MTF50/SFR 参考值。

黄金模型必须固定坐标原点、角度正方向、输出画布、边界填充方式和参数单位。否则 FPGA 与 PC 结果不一致时很难定位问题。

### 3.2 相机标定

相机标定不应在 FPGA 内实时求解。建议使用 PC 离线完成：

1. 打印或购买棋盘格标定板。
2. 从不同位置、不同角度拍摄 10～20 张图。
3. 使用 OpenCV `calibrateCamera` 等方法求取内参矩阵和畸变系数。
4. 将结果转换成定点格式和 FPGA 可读取的参数文件。
5. FPGA 运行时只执行映射和采样。

典型内参矩阵为：

```text
K = [ fx  0  cx ]
    [ 0  fy  cy ]
    [ 0   0   1 ]
```

典型畸变模型可以先使用：

```text
r2 = x^2 + y^2
x_d = x * (1 + k1*r2 + k2*r2^2) + 2*p1*x*y + p2*(r2 + 2*x^2)
y_d = y * (1 + k1*r2 + k2*r2^2) + p1*(r2 + 2*y^2) + 2*p2*x*y
```

第一版可只支持 `k1`、`k2`，并把 `p1`、`p2` 置零；第二版再增加切向畸变和 `k3`。

### 3.3 逆向映射

输出端每产生一个像素 `(u_out, v_out)`，就反向计算它在输入图像中对应的位置 `(u_in, v_in)`：

```text
输出坐标
   |
   v
去中心化/归一化
   |
   v
旋转或单应性逆变换
   |
   v
径向/切向畸变映射
   |
   v
恢复到像素坐标
   |
   v
从帧缓存取样
```

逆向映射比正向映射更适合视频输出，因为每个输出像素都有明确来源，避免正向投影产生空洞。

### 3.4 任意角度的实现路线

不要第一版就实现完整浮点三角函数。推荐分三级：

#### 级别 A：预设角度

在 PC 端预先计算 `sinθ`、`cosθ` 和偏移量，FPGA 只读取固定参数。先实现 `-45°、0°、+45°` 等几个角度。

#### 级别 B：参数化角度

通过 UART 或按键输入角度，FPGA 从 LUT 读取正弦/余弦，或使用 CORDIC 计算。角度范围可先限制在 `-45°～+45°`。

#### 级别 C：组合畸变模型

在角度旋转/透视后加入径向和切向畸变校正，支持从 PC 下发 `fx、fy、cx、cy、k1、k2、p1、p2`。

#### 最终组合模型

最终版本建议统一为一个可配置的逆向映射器，而不是把“旋转模块”和“畸变模块”做成互相独立的临时补丁：

```text
输出像素 (u,v)
    ↓
输出坐标归一化
    ↓
逆单应性/姿态变换 H^-1
    ↓
相机畸变模型逆映射
    ↓
输入像素坐标 (x,y)
    ↓
双线性插值
```

其中：

- `H` 用于表示任意角度、旋转和透视关系；
- `K` 用于相机内参；
- `k1、k2、k3、p1、p2` 用于镜头畸变；
- 参数由 PC 标定/计算后发送到 FPGA；
- FPGA 只负责高吞吐的逐像素映射和采样。

最终不要把矩阵求逆、相机标定和复杂优化放入实时 RTL。矩阵求解、参数拟合和标定属于 PC 侧；FPGA 侧实现确定性的参数化像素处理。

## 4. FPGA 硬件架构

建议的 RTL 模块如下：

```text
top
├── clk_pll
├── ov5640_config
├── camera_capture
├── rgb565_decoder
├── frame_sync
├── ddr3_frame_buffer
├── angle_parameter_ctrl
├── coordinate_mapper
├── fixed_point_math
├── pixel_interpolator
├── boundary_handler
├── hdmi_timing
├── video_overlay
├── uart_config
├── uart_status
└── debug_counter
```

最终版本还应增加以下逻辑能力：

- `transform_mode`：旋转、透视、径向、组合模式；
- `parameter_bank`：双参数组，用于帧边界安全切换参数；
- `frame_status`：帧计数、丢帧、越界、DDR3 欠载和插值异常计数；
- `quality_overlay`：叠加网格、中心点、边界框、当前角度和状态；
- `capture_trigger`：在测试时锁存指定帧，便于与上位机参考图对比。

### 4.1 `camera_capture`

负责采集 DVP 数据，识别一帧开始/结束和一行有效数据，输出统一的像素流：

```text
pixel_data
pixel_valid
line_start
line_end
frame_start
frame_end
```

该模块要处理摄像头时钟域和系统时钟域之间的跨时钟问题，不能直接把异步信号送入后级逻辑。

### 4.2 `ddr3_frame_buffer`

任意角度映射会造成非连续读地址，因此完整方案建议预留 DDR3 帧缓存。第一版可以采用单帧写入、显示端读取；稳定后再升级为乒乓缓冲。

需要验证：

- DDR3 IP 是否由当前 PDS 版本提供；
- 行突发读写能否满足像素吞吐量；
- 写入时钟和读取时钟是否独立；
- 帧切换时是否出现撕裂；
- 输入输出分辨率和像素格式。

如果 DDR3 调试成本过高，可先用 ROM/片上 RAM 读取测试图片，先验证坐标映射和插值模块。

### 4.3 `coordinate_mapper`

该模块是核心。它接收输出像素坐标和参数，输出：

```text
input_x_integer
input_y_integer
input_x_fraction
input_y_fraction
input_valid
```

建议使用 Q 格式定点数，例如 Q12.20 或 Q16.16。具体格式根据分辨率、参数范围和乘法器资源确定。第一版不要使用浮点 RTL。

### 4.4 `pixel_interpolator`

实现顺序：

1. 最近邻插值：只读取一个像素，最快速、最容易验证。
2. 双线性插值：读取四个邻域像素，画质明显更好。

双线性插值需要正确处理 RGB565 的三个颜色分量，建议先拆成 R/G/B 后计算，再重新打包。

### 4.5 `boundary_handler`

输入坐标超出图像范围时，统一处理为：

- 填充黑色；或
- 复制边缘像素。

初始方案建议填充黑色，逻辑最简单，且便于展示矫正区域边界。

最终版本应至少支持两种边界模式：黑色填充和边缘复制，并允许通过上位机切换。对越界像素必须有计数器，否则无法解释不同角度下画面边缘的黑区变化。

## 5. 测试卡与评价方案

### 5.1 低成本赛前方案

第一阶段不必购买昂贵专业卡，可以使用：

- A3/A4 棋盘格标定图；
- 黑白网格线；
- 自制倾斜黑色矩形/斜边图；
- 打印后贴到平整硬纸板。

它们足以完成标定流程、直线弯曲观察和 FPGA 前后效果对比。

### 5.2 专业图卡

如果最终需要更规范地报告 MTF50/SFR，再购买 ISO 12233/eSFR 图卡。专业图卡价格可能从数百元到数千元不等，首版不应把它作为项目启动前提。

### 5.3 验证指标

建议至少记录：

- 输入和输出分辨率；
- 实际帧率；
- 单帧延迟；
- FPGA 资源占用；
- 最大时钟频率；
- 矫正前后直线度误差；
- 矫正前后 MTF50/SFR；
- 边缘是否出现明显拉伸、断裂或黑洞；
- 不同角度下的稳定性。

### 5.4 完整测试矩阵

最终验收不能只测一个角度和一张图，至少应建立如下矩阵：

| 类别 | 测试内容 |
|---|---|
| 标定 | 不同距离、不同姿态、不同图卡位置下的内参重投影误差 |
| 角度 | 0°、正角度、负角度、大角度以及角度切换 |
| 畸变 | 仅径向、径向+切向、透视、组合模型 |
| 画质 | 最近邻与双线性插值，中心与边缘区域，水平与垂直方向 |
| 实时性 | 分辨率、帧率、处理延迟、持续运行时间 |
| 健壮性 | 参数越界、输入丢帧、DDR3 欠载、摄像头重新上电 |
| 对比 | PC 浮点参考、PC 定点参考、FPGA 输出三者的像素误差 |

最终报告应给出 FPGA 与 PC 黄金模型之间的最大绝对误差、平均绝对误差和可接受误差阈值，而不是只展示一张肉眼看起来正常的图片。

MTF50/SFR 的完整计算可以先放在 PC 上完成：FPGA 输出矫正画面，HDMI 采集卡或抓帧方式送到 PC，再用 Python/OpenCV 或专用工具分析。FPGA 内部只需回传必要统计值即可。

### 6.4 通信协议初稿

建议使用简单定长帧，避免初期引入复杂协议：

```text
帧头  命令  长度  数据  CRC16
0x55  1B    1B    N字节  2B
```

首批命令可以包括：

| 命令 | 用途 |
|---|---|
| `0x01` | 设置角度 |
| `0x02` | 设置内参 |
| `0x03` | 设置畸变系数 |
| `0x04` | 开关矫正 |
| `0x81` | 读取运行状态 |
| `0x82` | 读取帧率和错误计数 |

字段宽度和缩放比例在 RTL 与 PC 端确认后再固化，不要在未验证前写死为最终协议。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 题目中的“任意角度”定义不清 | 算法方向错误 | 尽快向官方技术群确认数学模型和验收方式 |
| OV5640 图像链路不通 | 无法开始算法演示 | 先跑官方例程，固定使用 VGA/RGB565 |
| DDR3 随机读效率不足 | 帧率低或画面撕裂 | 降低分辨率，采用行缓存/乒乓缓冲/突发读取 |
| 定点溢出 | 图像严重错位 | PC 端先做定点仿真，增加边界和溢出测试 |
| 双线性插值资源过高 | 时序不收敛 | 先最近邻，乘法分时或利用 DSP/硬核资源 |
| 标定参数不稳定 | 结果不可重复 | 固定焦距、曝光和测试距离，保存参数版本 |
| 只在 PC 上验证 | FPGA 现场效果不可信 | 早期就接入真实摄像头和 HDMI |

## 9. 初始完成标准

第一版里程碑可以定义为：

1. OV5640 能稳定采集 640×480 RGB565 图像。
2. FPGA 能通过 HDMI 显示原始画面。
3. PC 能通过棋盘格完成一次内参和畸变参数标定。
4. FPGA 能使用固定参数完成至少一个角度的图像矫正。
5. FPGA 画面与软件黄金模型在坐标、边界和直线形态上基本一致。
6. 能通过 UART 修改角度或开关矫正。

8. 支持组合变换，而不是只支持固定角度旋转。
9. 支持完整的内参和畸变参数链路。
10. 支持双线性插值和至少两种边界处理方式。
11. 支持上位机标定、参数管理、实时配置和测试报告生成。
12. 完成多角度、多图卡、多分辨率和长时间稳定性测试。
13. 给出 MTF50/SFR、直线度、像素误差、资源占用、帧率和延迟的可复现数据。
14. 完成最终视频、源码、文档和 PDS 工程交付。

项目使用队友已有的私有仓库 `Yling-1-PNG/pangu50k-distortion-correction`，以本地唯一正式目录 `C:\Users\Zhanglongsheng\Projects\pgl_project` 接入，不再创建另一份远端仓库。详细规则见同目录 `团队协作规范.md`。

1. 各成员独立克隆仓库并在自己的 VS Code/Codex 中工作；一个任务一条短分支，PR 写明目标、修改范围、测试与未验证项。Git 远端和仓库内文档是共同依据，聊天记录不能替代版本化源码或测试证据。

4. 区分 PC 测试、PDS 离线构建、实板功能测试与量化验收四级证据；任何分支都不得把低一级结果写成高一级完成。合并前至少由另一名成员审阅，硬件相关 PR 在持板机复测。
