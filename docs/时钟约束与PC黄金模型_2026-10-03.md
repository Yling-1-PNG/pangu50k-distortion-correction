# 时钟约束与 PC 黄金模型（2026-10-03）

## 1. 参考工程时钟核对

对象：`build/legacy_camera_after_ip/10_HDMI_DDR3_OV5640_test` 的官方摄像头+DDR3+HDMI 示例。只改动独立测试副本 `build/clock_audit_2026-10-03` 中的 `hdmi_ddr_ov5640_top.fdc`，原始资料包和安装后首次构建的副本均保留。

| 证据 | 数值/结论 |
|---|---|
| `source/rtl/pll/pll.idf:412–413` | IP 请求 `CLKOUT0=37.1250 MHz`。这是请求值，不应当作精确生成值。 |
| `source/rtl/pll/pll.v:27–35` 和综合网表 `synthesize/hdmi_ddr_ov5640_top_syn.vm` 的 `u_pll_e3` | `CLKIN_FREQ=50`、`STATIC_RATIOI=2`、`STATIC_RATIOF=49`、`STATIC_RATIO0=33`；相应分频为 `50×49/(2×33)=37.121212... MHz`。 |
| `source/rtl/sync_vg.v:40,45` | 行总周期 1650、帧总行数 750；按上述像素时钟约为 `29.997 fps`。 |
| 原 FDC 第 751 行及原时序报告第 68 行 | `multiply_by 27 / divide_by 20` 把时钟约成 67.500 MHz，与 PLL 配置不符。 |
| 测试副本 FDC 与新时序报告第 68 行 | 改为 `multiply_by 49 / divide_by 66`；PDS Lite 报告 `pix_clk 37.121 MHz`，与生成参数匹配。 |

测试副本的 `pds_shell.exe -project ... -run gen_bit_stream` 已完成编译、综合、布局布线、时序报告及 `.sbit` 生成。新报告中 `pix_clk` 预计路径频率 248.193 MHz，表明**已分析到的这组同步内部路径**有余量；不能外推为整个摄像头/DDR3/HDMI 通路时序完整闭合。

新旧 `report_timing/run.log` 均有 178 条 `not constrained`、38 条 `STA-3011` 无时钟端点警告。未约束端口包括 CMOS1/CMOS2 输入、HDMI 输出、DDR3 IO 和控制脚。下一轮约束需要分别核实 OV5640 PCLK 与数据/同步信号时序、HDMI 发送芯片输入时序、PCB 走线与 DDR3 IP 的约束边界；不能通过随意填 `set_input_delay 0` 或 `set_output_delay 0` 来消警告。FDC 尾部有多组 `set_clock_groups -asynchronous`，跨域路径须结合 RTL 同步结构逐项审查。板卡未连接，未验证真实视频帧率及输出。

将重复警告按**唯一端口**归类得到 133 个：CMOS1 13、CMOS2 13、DDR3 71、HDMI 视频 28、其他控制/状态 8。摄像头资料 `盘古50K开发板/4_IC_datasheet/OV5640/OV5640_DataSheet.pdf` 的 PDF 第 167 页给出的是 SCCB 配置总线时序，不能拿来当 DVP 像素数据的输入延迟。资料包 `盘古50K开发板/4_IC_datasheet/HDMI PHY/《MS7210 Datasheet-CN》-sp(1).pdf` 第 10 页列出数字视频输入与 PCLK 引脚，但本轮未从其正文提取到可靠的像素输入建立/保持时间。故本轮没有凭空添加 IO 延迟数值，也没有把 178 条警告标作已修复；下次需结合该 HDMI 芯片的完整时序资料、OV5640 DVP 模式、板卡原理图/PCB 及 PDS DDR3 IP 自带时序说明继续处理。

## 2. 可运行的 PC 参考模型

源码：`tools/golden_model.py`；数值测试：`tools/test_golden_model.py`。Python 环境已经有 OpenCV 4.11.0 和 NumPy 1.26.4。算法采用 Brown–Conrady 的 `k1,k2,p1,p2[,k3]`：每个输出像素先按角度或用户提供的 2×3 仿射矩阵逆变换到理想去畸变图，再由径向/切向方程找到畸变源图坐标，最后用 OpenCV 双线性 `remap` 采样。仿射矩阵是从去畸变坐标到输出坐标的**正向**矩阵；不能同时指定矩阵和非零 `--angle`。输出分辨率固定与输入相同，越界处填黑。输入是**单目**图像。

在 VS Code 项目根目录运行：

```powershell
py -3 -m unittest discover -s tools -p test_golden_model.py -v
py -3 tools\golden_model.py demo --output-dir build\golden_demo
```

`build/golden_demo` 中的 `01_ideal_grid.png`、`02_simulated_camera.png`、`03_corrected.png`、`04_corrected_rotated_17deg.png`、`05_corrected_affine.png`、`calibration_demo.json` 和 `affine_demo.json` 是**合成数据**，只能证明算法与工具调用，不是实际 OV5640 标定参数。四项单元测试分别检验零畸变恒等映射、与 OpenCV 去畸变映射的逐坐标吻合、旋转逆映射、通用仿射逆映射。合成网格中心裁剪区域相对于理想图的平均绝对误差，从模拟畸变的约 16.92 灰度级降低到矫正后的约 7.09；存在两次插值损失，不应期望零误差。

实际摄像头到手后，打印棋盘格、从多个角度拍摄不少于 3 张同尺寸图像（更多且覆盖视场更合适），用 **内角点数**指定 `--columns` 和 `--rows`，`--square-size` 单位自定但需一致：

```powershell
py -3 tools\golden_model.py calibrate --images 'photos\*.png' --columns 9 --rows 6 --square-size 20 --output calibration\ov5640.json
py -3 tools\golden_model.py correct --image photos\sample.png --calibration calibration\ov5640.json --angle 17 --output build\corrected_17deg.png
py -3 tools\golden_model.py correct --image photos\sample.png --calibration calibration\ov5640.json --affine build\golden_demo\affine_demo.json --output build\corrected_affine.png
```

标定输出包括 3×3 内参矩阵、`k1,k2,p1,p2,k3`、图像大小、标定 RMS 重投影误差和接受的照片列表。它是以后定点 RTL 对比的浮点“黄金模型”；校正参数必须与实际摄像头分辨率及镜头匹配。本版尚未实现透视单应矩阵、定点量化、MTF50/SFR、Gamma/直方图或 FPGA 映射单元。
