# OV5640 200°鱼眼镜头：到货前离线准备（2026-10-05）

## 结论与边界

- 用户确认候选“标准版”和“200°鱼眼版”共用官方 OV5640 模块的接口与例程，仅镜头不同；交流群反馈标准版实际畸变不明显，展示图中的鱼眼画面外围有明显桶形弯曲。因此将鱼眼镜头作为当前**采购/标定优先方案**，但不把交流群照片当作原始帧或标定样本，也不由照片推算视场、内参、畸变系数或矫正质量。
- 官方赛题 `docs/紫光赛题.pdf` PDF 第 12–14 页：基础任务含二阶径向畸变（及切向畸变）坐标映射、插值、采集缓存显示；高阶任务含动态角度/仿射、流水线优化、自适应预处理。鱼眼模型是为了真实强畸变镜头增加的**扩展分支**，不得替代或虚报基础任务模型的验证。
- “200°”是商品标称视场角，方向与实测范围尚未确认。普通透视平面不能保留超过 180° 的完整视场。方案应比较裁切和保留视场的取舍，不承诺全画幅无黑边、无拉伸或恢复镜头本身未解析出的细节。
- 鱼眼镜头不改变 OV5640/DVP/DDR3/HDMI 传输链，也不能解决 8 位 DVP RGB565 1080p30 的输入带宽问题。官方视频例程、Lite 离线位流和 37.121 MHz 像素约束的状态仍参见 `盘古50K资料包1_研读记录.md` 与 `时钟约束与PC黄金模型_2026-10-03.md`。

## 已实现的 PC 参考模型

- `tools/golden_model.py` 保持 Brown–Conrady 分支 `k1,k2,p1,p2[,k3]`，用于赛题所述基础模型。该分支没有因鱼眼选型被删除或改称鱼眼模型。
- 新增 `tools/fisheye_model.py`，采用 OpenCV 鱼眼角度模型：`theta=atan(r)`，`theta_d=theta(1+k1 theta²+k2 theta⁴+k3 theta⁶+k4 theta⁸)`；每个输出像素先逆向变换（旋转或通用 2×3 仿射），再映射回输入相机坐标，最后双线性采样。公式和 API 依据：[OpenCV 4.11.0 鱼眼模型文档](https://docs.opencv.org/4.11.0/db/d58/group__calib3d__fisheye.html)。这只是浮点 PC 黄金模型，不是 FPGA 定点实现。
- `calibrate` 命令可从**同一台真实相机、同一成像模式**的棋盘格原始帧计算鱼眼 `K`、`D`、RMS 和已采纳照片列表。少于 8 张可用不同姿态照片会报错；8 是程序下限，不是高质量标定保证。现场建议采集约 20–30 张、覆盖中心/四角与多种倾斜，剔除模糊、过曝、角点缺失帧，检查重投影误差和独立网格照片的直线度。
- `correct` 命令支持 `--balance 0..1`（0 偏向裁切填满画面，1 偏向保留视场）、`--angle` 或 `--affine`。输出 `coordinate_in_bounds` 仅统计映射坐标落入源图矩形的比例，**不会检测鱼眼成像圆外的黑区，也不是画质或有效视场的最终指标**。鱼眼记录带 `model: opencv_fisheye`，与普通模型 JSON 不可混用。
- `tools/test_fisheye_model.py` 的 4 项离线测试涵盖两个保留视场设置与 OpenCV 官方映射的数值一致性、动态仿射/角度下的独立投影点对照、图像采样及边界掩码、错误模型/参数拒绝。连同原普通模型测试，本机 Python 3.10 / OpenCV 4.11.0 下 8 项测试通过（2026-10-05）。**尚无真实鱼眼原始帧，因此未验证标定质量、矫正直线度、MTF50/SFR 或鱼眼实板输出。**

## 复现方式（PowerShell，在正式项目根目录）

```powershell
py -3.10 -B -m unittest discover -s tools -p 'test_*model.py' -v
py -3.10 -B tools/fisheye_model.py calibrate --images 'data/fisheye/calibration/*.png' --columns 9 --rows 6 --square-size 20 --output 'data/fisheye/calibration.json'
py -3.10 -B tools/fisheye_model.py correct --image 'data/fisheye/raw_grid.png' --calibration 'data/fisheye/calibration.json' --balance 0 --output 'build/fisheye_cropped.png'
py -3.10 -B tools/fisheye_model.py correct --image 'data/fisheye/raw_grid.png' --calibration 'data/fisheye/calibration.json' --balance 0.7 --angle 17 --output 'build/fisheye_wide_rotated.png'
```

以上图像路径只是**到货后的目录约定**，当前不存在；`--columns/--rows` 为实际棋盘格的内角点数，`--square-size` 为实物方格边长，示例值 9×6、20 mm 不得作为未经测量的事实。完整画面必须来自相机原始输出，不得用手机拍显示器照片做标定。

## 到货后第一轮验收与后续分支

1. 先核对板卡/相机修订、供电和引脚；LED/JTAG、DDR3、HDMI、OV5640 单路原始画面逐项验证。记录真实输入分辨率、像素格式、帧率、是否自动曝光/裁剪/缩放、输出分辨率和长期稳定性。保持镜头对焦与成像模式固定，标定后更改分辨率/裁剪需重新核对 K 和 D。
2. 保存至少一组**原始帧**：多姿态棋盘格、独立网格图卡、倾斜黑方块/斜边及普通场景。记录图卡尺寸、拍摄距离、照明、镜头版本和采集模式。交流群的显示器照片只用作选型线索。
3. 用鱼眼模型标定并扫描 `balance` 不同档位；记录 RMS、网格直线度、有效内容区域、黑边/边缘拉伸与清晰度。展示“裁切/画质”档和“宽视场”档，但最终展示档位由实测决定，不预先承诺数值。
4. 在**明确的有效 ROI** 内对赛题要求的二阶径向/切向模型单独拟合和验证，保存其独立参数与误差，不将 OpenCV 鱼眼参数 `k1..k4` 误传给 Brown–Conrady RTL。若基础模型无法达到目标范围，再将鱼眼专用映射作为扩展通路；两种模式在上位机、RTL 和报告中明确区分。
5. HDL 阶段对同一批真实原始帧固定“输出像素 → 逆向角度/仿射 → 镜头映射 → 四邻域读取 → 双线性插值”的输入输出契约；先在 PC 模型形成坐标/像素 golden vectors，再定点化、仿真、PDS 构建、实板逐像素比对。鱼眼与普通映射可以共用 DDR3 帧缓存、坐标接口、采样和显示链，不能把已通过的 PC 浮点模型等同 FPGA 完成。
6. 最终按题面提交端到端帧率/延迟、LUT/FF/DSP、时序约束、直线度及 MTF50/SFR 等实测。成像圆、过大变形和超出输入的坐标要定义裁切/填充策略；不承诺插值能创造不存在的边缘细节。

## 当前未验证清单

- 相机实际镜头型号、标称“200°”的水平/垂直/对角定义与真实投影函数。
- 鱼眼镜头实拍原始帧、标定参数、独立验证集、可用 ROI 和 MTF50/SFR。
- 基础二阶模型能覆盖的真实视场范围；鱼眼扩展是否需要更多 DSP/BRAM、是否满足目标帧率。
- 相机接到盘古 50K 后的 DDR3/HDMI 画面与输出时序，以及当前未约束 IO 的板级边界。
